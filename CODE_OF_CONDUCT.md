# Code of Conduct

## Our standard

The `gof` project is built around rigor, direct communication, and respect for
the people doing the work. We expect contributors to:

- engage with technical disagreements in good faith
- criticize ideas, code, and decisions without attacking people
- respect review boundaries, governance rules, and project quality bars
- avoid harassment, intimidation, discrimination, or abusive behavior
- keep discussions constructive, specific, and professional

## Unacceptable behavior

Unacceptable behavior includes:

- personal attacks, insults, or demeaning language
- harassment, stalking, or unwelcome sexual attention
- doxxing or publishing private information without consent
- threats of violence or attempts to intimidate contributors
- trolling, bad-faith derailing, or repeated low-effort disruption
- deliberate sabotage of discussions, reviews, or project infrastructure

## Scope

This Code of Conduct applies in project spaces, including:

- GitHub issues, pull requests, reviews, and discussions
- project documentation and governance threads
- public conversations where someone is representing the project

## Enforcement

Project maintainers are responsible for clarifying and enforcing this Code of
Conduct. They may remove comments, close discussions, block contributors, or
take other action when behavior violates project standards.

## Reporting

If you need to report a violation, contact the maintainer through the
repository owner's GitHub contact channel and include:

- a link or reference to the incident
- what happened
- any relevant context or screenshots

Maintainers will review reports as privately as practical and take action based
on the severity and pattern of behavior.

## Project-specific expectation

`gof` is intentionally high-discipline engineering work. Strong technical
critique is welcome. Personal hostility is not.
