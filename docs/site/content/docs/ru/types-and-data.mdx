## Встроенные scalar values

Сейчас базовые scalar types такие:

- `int`, `string`, `bool`, `json`

Есть также `unit`, который означает "нет осмысленного значения", и runtime-level
values вроде tasks, channels и cancellation tokens.

Parameterized annotations: `list[int]`, `dict[int]`, `channel[int]`, `task[int]`, `Result[int, RuntimeError]`.

## Списки

```gof
values: list[int] = [10, 20, 30]
return values[0] + len(values)
```

Текущие правила:

- список должен быть однородным, когда type layer может это вывести
- `append(list, value)` возвращает новый список
- `first(list)` и `last(list)` возвращают `Result[element, RuntimeError]`
- `slice(list, start, end)` возвращает `Result[list[element], RuntimeError]`
- `reverse(list)` и `sort(list)` возвращают новые списки
- `min(list)` и `max(list)` возвращают `Result[element, RuntimeError]`

<Callout type="info">
  List helpers в `gof` — это явное построение нового значения, а не скрытая мутация.
</Callout>

## Словари

```gof
store: dict[int] = {"ok": 7, "warn": 2}
return store["ok"] + len(store)
```

```gof
base: dict[int] = {"ok": 7}
next = insert(base, "warn", 2)
return next["warn"]
```

Текущие правила: строковые ключи, `dict()`, `insert(dict, key, value)`, `keys(dict)`, `values(dict)`, `contains(dict, "key")`, `len(dict)`.

## Числовые выражения

```gof
value = -(8 + 2) / 5
rest = value % 2
```

## Сравнения

- equality через `==` и `!=` для `int`, `string`, `bool`, `json`, `unit`, `list[T]`, `dict[T]`, `struct`, `enum`, `Result[T, E]`
- ordering через `<`, `<=`, `>`, `>=` только для `int` и `string`

## Struct

```gof
struct Point:
    x: int
    y: int

fn total(point: Point) -> int:
    return point.x + point.y
```

## Enum

```gof
enum JobState:
    Ready
    Running(pid: int)
    Failed(message: string)
```

Unit-вариант: `EnumName.Variant`. Payload-вариант: `EnumName.Variant(value, ...)`.

## Result

```gof
fn halve(value: int) -> Result[int, string]:
    if value % 2 != 0:
        return Result.Err("odd")
    return Result.Ok(value / 2)
```

- `Result.Ok(value)` и `Result.Err(error)` — конструкторы
- postfix `expr?` распаковывает `Ok` и делает ранний `return` на `Err`
- operational helpers тоже возвращают `Result`

## Option

`Option[T]` — явное отсутствие значения: либо `Option.Some(value)`,
либо `Option.None`. Null в языке нет.

```gof
fn find_user(id: int) -> Option[string]:
    if id == 1:
        return Option.Some("gofer")
    return Option.None

fn greet(name: Option[string]) -> string:
    match name:
        Option.Some(value):
            return "hello, " + value
        Option.None:
            return "hello, stranger"
```

- `Option.Some(value)` — конструктор с payload; `Option.None` — unit-вариант без скобок
- отсутствие разрешается исчерпывающим `match` или `unwrap_or(default)`
- receiver-хелперы: `opt.unwrap_or(default)`, `opt.is_some()`, `opt.is_none()`
- postfix `?` к `Option` не применяется — это оператор `Result[T, E]`
- неявной конверсии между `T` и `Option[T]` нет ни в одну сторону

## Кортежи

`(T1, T2, ...)` — структурный тип фиксированной арности: гетерогенные
члены, структурная идентичность, дешёвое копирование.

```gof
fn bounds() -> (int, int):
    return (1, 100)

fn main() -> int:
    pair: (int, string) = (1, "one")
    (lo, hi) = bounds()
    mut (a, b) = (10, 20)
    for (x, y) in [(1, 2), (3, 4)]:
        a = a + x * y
    return pair.0 + lo + hi + a + b
```

- кортежи — два и более членов; `()`, `(T)` и висячие запятые отвергаются парсером
- тип пишется `(T1, T2, ...)`; вариант `tuple[...]` отвергается с fix-it
- `expr.N` — доступ к N-му члену для канонических десятичных литералов
- деструктуризация: в bind-стейтментах, `for`-биндингах и payload-позициях match; листья — идентификаторы или вложенные кортежи
- `mut (a, b) = ...` распределяет `mut` на каждый лист
- правая часть вычисляется до биндинга листьев — `(a, b) = (b, a)` это свап
- равенство — попарно при сравнимых членах; упорядочивание — лексикографически слева направо при `int`/`string`-членах
- рендеринг: `(member, member, ...)` рекурсивно

## RuntimeError

Встроенный operational error enum: `EnvMissing`, `Io`, `ChannelClosed`, `Cancelled`, `TaskFailed`, `TaskPanicked`, `ParseInt`, `EmptySequence`, `Slice`, `Json`, `Csv`, `Toml`, `HttpRequest`, `HttpStatus`.

## Замыкания

Анонимные функции — выражения со snapshot-моделью захватов.

```gof
fn make_adder(n: int) -> fn(int) -> int:
    return fn (x: int) -> int:
        return x + n

fn apply_twice(op: fn(int) -> int, value: int) -> int:
    return op(op(value))

fn main() -> int:
    add5 = make_adder(5)
    assert(apply_twice(add5, 2) == 12, "expected 7 then 12")
    square = fn (n: int) -> int:
        return n * n
    assert(square(9) == 81, "expected 81")
    return 0
```

- `fn (x: int) -> int:` — выражение: параметры строго с аннотациями, `-> Ret` опционален, блок — часть выражения
- тип замыкания: `fn(ParamTypes) -> RetType` — точная структурная совместимость, без variance
- захватываются только immutable внешние биндинги, значения снапшотятся при создании; `fn`-выражение в цикле создаёт замыкание на каждую итерацию
- handle-захваты разделяют ресурс: каналы проходят в `go closure(args)`
- `defer` захватывает ЗНАЧЕНИЕ замыкания при регистрации: переприсваивание после defer всё равно вызовет зарегистрированное замыкание
- замыкания не участвуют в равенстве, упорядочивании и печати

## Протоколы

Протоколы — контракты методов; конформность явная.

```gof
protocol Shape:
    fn area(self: Self) -> int
    fn name(self: Self) -> string

struct Circle:
    radius: int

fn Circle.area(self: Circle) -> int:
    return self.radius * self.radius * 3

fn Circle.name(self: Circle) -> string:
    return "circle"

impl Circle: Shape

fn main() -> int:
    print(Circle(2).name())
    print(Circle(2).area())
    return 0
```

- `protocol Name:` объявляет сигнатурные `fn`-требования; ресивер аннотируется `Self`, `mut receiver: Self` — мутирующее требование
- `impl Struct: Protocol` объявляет конформность явно: совпадающие методы сами по себе НЕ конформят
- проверка требует от каждого требования метод с идентичными типами параметров, возвратом и mutability ресивера после подстановки `Self`
- generic-функции несут границы: `fn describe[T: Shape](shape: T)` — тело вызывает только bounded-методы, вызовы проверяют конформность выведенного типа
- имена протоколов не могут быть типами значений: конформность v1 — только через generic

## Методы

```gof
struct Point:
    x: int
    y: int

fn Point.with_bonus(self: Point, extra: int) -> int:
    return self.x + self.y + extra
```

Receiver type объявляется в имени метода, первый параметр должен совпадать.

## Как правильно думать о данных в `gof`

- scalar — для простых значений
- list — для упорядоченных однородных данных
- dict — для string-keyed lookup
- struct — для shaped data
- enum — для закрытого набора состояний
- Result — для явного recoverable success/error flow
